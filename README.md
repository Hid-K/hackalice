# hackalice

Полуавтоматическое рутирование **Яндекс Станций** (получение root и постоянного
SSH) на устройствах, которые **принадлежат вам**. Основной сценарий —
интерактивный мастер, который шаг за шагом проведёт от настройки изолированной
сети до входа `ssh root@колонка`.

> **Дисклеймер.** Откат прошивки, аппаратный сброс и блокировка OTA стирают
> настройки колонки и лишают гарантии. Используйте только на своём устройстве
> и на свой риск.
>
> Инструмент использует наработки сообщества
> [Yandex Station Extended](https://hackalice.me) и проект
> [lite-kit](https://github.com/krevetkqqq/lite-kit) — с ними проект не связан.

## Как это работает

Инструмент поддерживает два метода (источник — вики
[hackalice.me](https://hackalice.me) и репозиторий lite-kit):

1. **Подмена DNS** (`method=dns`) — Станция Миди (YNDX-00054), Станция 2, 3
   (Orion), Стрит, Умный хаб и др. Прошивка не трогается: колонка сбрасывается
   обычным способом, привязывается к изолированной сети, где DNS-домены Яндекса
   указывают на сервер lite-kit, который в ответе `get_sync_info` активирует
   сетевой ADB (`adbd.remoteActivation`) — порт 5555 с root.
2. **Откат прошивки** (`method=downgrade`) — Станция Лайт 1 (YNDX-00025) на
   сборках после 21.10.2026 (и Мини 2/Мини 1): аппаратный сброс загружает
   factory-образ из recovery, он доверяет серверу обновлений lite-kit, который
   отдаёт проверенную прошивку с открытым ADB (у Лайт — `.46`), затем привязка
   и ADB root.

Оба метода дальше одинаковы: через ADB (root) на колонку ставится статический
**dropbear** (собирается кросс-компилятором под aarch64), SSH прописывается в
автозагрузку, обновления OTA блокируются.

Физические шаги (кнопки на колонке, привязка в приложении «Дом с Алисой»)
мастер не может выполнить сам — он показывает инструкцию и ждёт подтверждения.

## Установка и зависимости

```bash
# Debian 12/13
pip install -r requirements.txt        # rich + questionary
# или глобально: sudo pip install .
```

**Системные программы ставить руками не нужно.** При каждом запуске hackalice
проверяет утилиты, нужные выбранной команде, и недостающие доустанавливает
сам через `apt-get` (non-interactive). Единственное ручное действие — один раз
разрешить эту установку, запустив инструмент через `sudo`.

| Группа | Утилиты (пакеты) | Когда |
|---|---|---|
| ядро | `adb`, `nmcli` (network-manager), `dnsmasq-base`, `iptables`, `ip` (iproute2), `ping` (iputils-ping), `git`, `curl`, `ssh`/`ssh-keygen` (openssh-client), `openssl`, `iw`, `python3` | всегда, при каждом запуске |
| сборка dropbear | `make`, `gcc-aarch64-linux-gnu`, `dpkg-dev`, `file`, `zlib1g-dev` | `build-dropbear`, `install-ssh`, визард |
| опционально | `dig` (bind9-dnsutils), `readelf` (binutils) | не требуются, проверяются мягко |

Нужно **два** сетевых интерфейса: один — интернет (Wi-Fi или Ethernet),
второй Wi-Fi адаптер — под точку доступа. Проверка: `iw list | grep -A12
"Supported interface modes"` — должен быть режим `AP`. Для сборки dropbear
в apt-источниках должен быть включён `deb-src` (tool подскажет точную команду,
если его нет).

## Быстрый старт

```bash
sudo hackalice            # или: sudo python3 -m hackalice
```

Мастер проведёт по шагам:

| Шаг | Что происходит |
|-----|----------------|
| 1   | Проверка root и системных зависимостей (предложит поставить через apt) |
| 2   | Выбор **модели** станции (реестр моделей, поддержка расширяется) |
| 3   | Выбор **интерфейсов**: интернет и точка доступа (с проверкой AP-режима) |
| 4   | SSID/пароль точки доступа + **статический IP по MAC** (по умолчанию 10.42.0.200 — колонка всегда получает один адрес, искать её после ребутов не нужно) |
| 5   | SSH-ключ: активный / из хранилища / **создать новый** / свой путь (+ метка колонки) |
| 6   | Откуда взять dropbear: собрать или готовый бинарник |
| 7   | Сводка и подтверждение |
| A–I | Исполнение: сеть → прошивка → dropbear → сервер → **сброс (вручную)** → **привязка (вручную)** → ожидание колонки → установка SSH → очистка |

Выборы сохраняются в `~/.config/hackalice/config.json` и подставляются при
следующем запуске.

## SSH-ключи

Хранилище ключей: `~/.config/hackalice/keys` (меняется `--keys-dir`).
В визарде (шаг 5) можно: взять активный ключ, выбрать из хранилища,
**создать новый** или указать свой путь. Метка колонки (например, «кухня»)
записывает маппинг «колонка → ключ» в конфиг: можно держать один ключ на
несколько колонок или свой на каждую.

```bash
hackalice keys list                        # ключи + маппинг колонок
hackalice keys create --name kitchen       # сгенерировать пару ed25519
hackalice keys use --name main             # сделать ключ активным

# добавить новый ключ на УЖЕ прошитую колонку (SSH с текущим ключом,
# фолбэк — ADB root; переустановка не нужна):
hackalice add-key --key-name kitchen --label кухня --device-ip <IP>
hackalice add-key --key ./id_new.pub --device-ip <IP>
```

### Несколько колонок в домашней сети

```bash
hackalice find                             # инвентаризация: все SSH-устройства сети,
                                           # наши колонки помечены (ключ/метка/MAC)
hackalice verify --label кухня             # операции с конкретной колонкой
hackalice unbind --label спальня
hackalice add-key --key-name new --label спальня
```

`--label` подставляет ключ/IP/MAC колонки из конфига. Нешитые колонки по SSH
не видны (его там нет) — их опознают по MAC в списке клиентов роутера.

## Пошаговые команды (для продвинутых)

```bash
sudo hackalice check         # окружение, интерфейсы, модель
sudo hackalice net-up        # hotspot + DNS + NAT
sudo hackalice fw            # клон lite-kit, патчи, загрузка прошивки .46
sudo hackalice build-dropbear
sudo hackalice serve         # сервер отката в фоне (лог ~/lite-kit/run/server.log)
# ...аппаратный сброс колонки и привязка на телефоне...
sudo hackalice wait-device   # дождаться root-ADB у колонки
sudo hackalice install-ssh   # dropbear + автозапуск + блок OTA + reboot
sudo hackalice cleanup       # стоп сервера, снять сеть (--flush-nat — и NAT)
sudo hackalice unbind        # отвязка от аккаунта по SSH (root/SSH остаются)
sudo hackalice verify        # проверка SSH и OTA-блока
hackalice models             # реестр моделей
hackalice interfaces         # список интерфейсов
```

Параметры можно передавать флагами (`--model lite-1 --ap-iface ... --inet-iface
... --device-ip ...`) — без флагов берутся сохранённые настройки.

Старый однофайловый запуск `sudo python3 alice_root.py` тоже работает —
это обёртка над пакетом.

## Поддерживаемые модели

| Ключ | Модель | Метод | Статус |
|------|--------|-------|--------|
| `midi` | **Яндекс Станция Миди (YNDX-00054)** | подмена DNS | поддерживается |
| `lite-1` | Яндекс Станция Лайт (YNDX-00025) | откат на .46 | поддерживается |
| `mini-2` | Яндекс Станция Мини 2 (YNDX-00020) | откат на .46 | экспериментально |
| `mini-1` | Яндекс Станция Мини 2019 (YNDX-0004) | откат | экспериментально |
| `station-2`, `station-3`, `station-street`, `hub` | Станция 2 / 3 / Стрит / Умный хаб | подмена DNS | экспериментально |
| `lite-2`, `mini-3`, `mini-3-pro`, `station-max`, `station-1`, `fiero-hi` | остальные | свои методы сообщества | в планах |

Станция Миди (YNDX-00054, платформа `cucumber`, Amlogic A5): root получается
DNS-методом **без отката прошивки** — сброс, привязка к сети с нашим DNS,
сервер lite-kit в обычном режиме активирует ADB. Сброс Миди: кнопка
отключения микрофонов на задней панели (или центральная сенсорная) удерживается
при подаче питания до сообщения о начале сброса.

Новые модели добавляются в `hackalice/models.py` (класс `ModelSpec`): метод,
платформа, архитектура, прошивка для отката (если нужна) и инструкция
аппаратного сброса. Весь остальной код читает реестр и не зависит от модели.

## Что переживает полный сброс (Миди/eMMC)

Сброс у Миди стирает только `/data`: dropbear, ключи, ADB-маркеры и логи
удаляются. Но правки в **корне** (system, ext4) сохраняются: обёртка
`S99quasar`, хук в `onboot.sh`, OTA-заглушка, `/etc/hosts`, ключ в
`/root/.ssh`. На стоковой колонке после сброса они инертны, кроме
OTA-заглушки — **обновления прошивки остаются заблокированными** до
повторного root и удаления заглушки. Бэкапы оригиналов (`/data/*.orig`)
при сбросе теряются — после установки сохраните `/data/boot_diag.txt`,
`/data/onboot.sh.orig` и `/data/S99quasar.orig` на ноутбук.

## Типовые проблемы

* Колонка в hotspot пишет «нет интернета», в `server.log` только
  `generate_204` и нет `get_sync_info`: у Станций свой DNS-резолвер
  (unbound), который ходит к DNS Яндекса напрямую — hackalice перехватывает
  весь udp/tcp 53 через DNAT (фаза A). Если симптом повторяется, проверьте
  форвардинг (`sudo iptables -vnL DOCKER-USER` — счётчик AP→inet растёт во
  время привязки) и что порт 53 занят dnsmasq NetworkManager'а.
* `adb connect` → `No route to host`: колонка отвалилась от hotspot —
  `sudo hackalice net-up`, проверьте `ip neigh`.
* «Что-то пошло не так» при привязке: телефон подключён к точке доступа
  `AliceSetup` — Wi-Fi на телефоне должен быть включён, но отключён от сетей
  (приложению нужно видеть список сетей), интернет — через мобильные данные.
  Либо не выдержан тайминг сброса (у каждой модели — в реестре `models.py`).
* `install-firmware.sh` виснет: используйте `hackalice fw` (патченные
  таймауты curl + неинтерактивный запуск).
* После reboot adb refused: колонка успела обновиться — повторите откат,
  до `install-ssh` не выпускайте её в WAN.

## Благодарности и источники

Методы получения доступа и знания об устройстве прошивок взяты из открытых
источников сообщества:

* вики [Yandex Station Extended](https://hackalice.me) — устройство моделей,
  DNS-метод, диагностика и восстановление;
* репозиторий [lite-kit](https://github.com/krevetkqqq/lite-kit) — сервер
  разблокировки (eQuasar), установщик прошивок.

Проект hackalice **не связан** с Yandex Station Extended, его авторами,
сообществом `@hackalice` и ООО «Яндекс» — это независимая реализация
публично известных методов для собственных устройств. Все вопросы по
работе конкретных методов — в их вики и чате; по коду этого инструмента —
в issues этого репозитория.
